# Handhold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local Claude mod that captures every turn as OTel GenAI traces, judges the person's prompts against the Altitude/Depth/Range rubric, nudges Claude and the person in the moment, and offers reflection over time.

**Architecture:** One function-hooks plugin in `plugin/`. `hooks/register.ts` wires engine events to four concern folders under `plugin/src/`: `capture`, `mentor`, `nudge` and `reflect`, plus `shared`. Pure logic (span building, rubric, parsing, aggregation) is plain functions tested directly. Engine-facing code is tested through `claude-code/testing`.

**Tech Stack:** TypeScript (ES modules), the Claude Code mod API (`claude-code`, `claude-code/testing`), `claude plugin validate`, `claude plugin test`, `tsc`.

**Spec:** `docs/superpowers/specs/2026-11-15-handhold-design.md`

## Global Constraints

- All local: no MCP, no network calls except `$.model.complete` judge calls.
- Plugin name `handhold`; command `/handhold` with subcommands `review`, `export`, `quiet`, `pane`.
- Pre-send judge: `claude-haiku-5-5`, `timeoutMs: 2000`. Post-answer judge: `claude-opus-5-5`, `timeoutMs: 20000`. Both overridable through `userConfig`.
- Trace path: `~/.handhold/traces/<session-id>/<turn-seq>-<turnId>.jsonl`, one file per turn, written once at `turn.complete`. `~` is resolved with `$.env.get("HOME")`.
- `redact` ∈ `none` (default) | `tool-results` | `all-tool-io`; a redacted value is the string `"[redacted]"`.
- Notes: at most one note per 3 turns, only when warranted and some score ≤ 1.
- Hidden context: only when warranted and some score ≤ 1. Back-off after 2 declines of a technique, for the rest of the session.
- Standing brief: section id `handhold:ambition`, `scope: 'session'`, under 250 tokens.
- Techniques (closed list): `goal-beyond-the-goal`, `durable-workflow`, `insist-on-instruments`, `unreasonable-goal`, `challenge-assumptions`, `produce-new-knowledge`, `outside-judge`, `nouns-to-verbs`, `assemble-the-crew`.
- `RUBRIC_VERSION = "1"`.
- No Handhold failure blocks, rewrites or delays a prompt beyond 2 s; every hook falls through to `next(e)` on error.
- Engine types live at `<plugin>/.claude-plugin/types/` once the mod has loaded. Before that, use the skill's `types/claude-code.d.ts`. Grep there for any signature this plan names.

## Review Focus

1. **A turn interrupted mid-tool (`isAborted`)**: its open `execute_tool`/`chat` spans close with `status.code=ERROR`, the file is still written, and the next turn starts clean. Test in Task 4.
2. **Huge tool results (multi-MB file reads) pushing a turn file past the 4 MiB `$.fs.write` limit**: attribute values over 64 KiB are truncated with the suffix `…[truncated]`, and the write succeeds. Test in Task 3.
3. **Judge returning prose around its JSON, or a technique not on the list**: the JSON object is extracted; an unknown technique, or a score outside 0–3, gives `null`. Test in Task 5.
4. **Two prompts submitted back-to-back while the pre-send judge is still running**: each gets its own assessment, and no hint is attached to the wrong prompt. Test in Task 6.
5. **`/handhold review` with no trace files yet, or a corrupt JSONL line**: it answers "No turns recorded yet." or skips the bad line; it never throws. Test in Task 8.

### Task 4: Capture hooks (turns, model steps, tools, subagents)

**Files:**
- Create: `plugin/src/capture/hooks.ts`
- Modify: `plugin/hooks/register.ts`, `plugin/types/index.d.ts`, `plugin/test/capture.test.ts`

**Interfaces:**
- Consumes: `TurnSpans`, the attribute builders, `writeTurn`, `safe`, `readConfig`
- Produces:
  - `registerCapture(on: On, cfg: Config): CaptureApi`
  - `type CaptureApi = { onTurnClosed(cb: (t: ClosedTurn) => void): void; addSpan(turnId: string, name: string, attributes: Record<string, unknown>): void }`. `addSpan` adds a closed child of the turn's root and is used for `handhold.assess`.
  - `type ClosedTurn = { turnId: string; seq: number; prompt: string; answer: string; toolNames: string[]; agentTypes: string[]; isAborted: boolean; durationMs: number }`
- Hook mapping (spec §3):

  | Event | Action |
  |---|---|
  | `prompt.submit` (skip when `e.command` or `e.isMeta`) | Store `e.text` as the pending prompt for the next main-loop `turn.start` |
  | `turn.start`, no `agentId` | New `TurnSpans`; open root `invoke_agent claude` with `gen_ai.input.messages = [{role:'user',parts:[{type:'text',content:e.text}]}]` |
  | `turn.start` with `agentId` | Open `invoke_agent <subagentType>` under the `execute_tool` span recorded for that agent at `agent.spawn` |
  | `agent.spawn` | `await next(e)`; map `result.agentId` to the open `execute_tool` span whose call id equals `e.tool_use_id`; keep `subagentType` |
  | `turn.step` (async generator) | Open `chat <e.model>` under the loop's current agent span; re-yield every chunk; on `await stream.result`, set `usageAttrs(result.usage)` and `gen_ai.output.messages` (text from `answer`, `tool_call` parts from `toolUses`), and `gen_ai.response.finish_reasons=[stopReason]`; close |
  | `tool.call` | Open `execute_tool <e.tool>` with `toolAttrs(e.tool, e.tool_use_id, input)`; `await next(e)`; set `toolResultAttrs`; close with `ERROR` when `isError` |
  | `turn.complete` with `agentId` | Close that agent span |
  | `turn.complete`, main loop | Set root output to `e.answer`; `closeAll` with `ERROR "aborted"` when `e.isAborted`; close root; `writeTurn`; call `onTurnClosed` subscribers; drop the turn from state |
  | `session.end` | For every turn still open: `closeAll` with `{ code:'ERROR', message:'session ended' }` and `writeTurn` |
- Open turns are kept in `$.state` atom `handhold.turns: Shaped<Record<string, SerializedTurnSpans>>`. `TurnSpans` needs `toJSON()` and `static from(json)`, because module variables reset on reload. The sequence counter is the atom `handhold.seq: Shaped<number>`.

### Task 6: Judge and pre-send nudging (brief, hidden context, back-off)

**Files:**
- Create: `plugin/src/mentor/judge.ts`, `plugin/src/nudge/brief.ts`, `plugin/src/nudge/context.ts`, `plugin/src/nudge/backoff.ts`, `plugin/test/nudge.test.ts`
- Modify: `plugin/hooks/register.ts`, `plugin/types/index.d.ts`

**Interfaces:**
- Consumes: `RUBRIC_TEXT`, `parseAssessment`, `isTrivial`, `needsNudge`, `assessAttrs`, `CaptureApi.addSpan`, `Config`
- Produces:
  - `judge($: Engine, input: { prompt: string; phase: 'pre'|'post'; turnSummary?: string; recent: Assessment[] }, cfg: Config): Promise<Assessment | null>`. It calls `$.model.complete({ model, system: RUBRIC_TEXT, prompt, maxTokens: 600, timeoutMs })`, using the fast model and pre timeout for `pre`, the full ones for `post`. It returns `null` on `isAnswered:false`, a rejection or a parse failure, logging one debug line.
  - `BRIEF: PromptComposeSection` (`{ id:'handhold:ambition', scope:'session', text }`): the text is spec §5 channel 1, kept under 250 tokens (test: `text.split(/\s+/).length < 190`).
  - `hintFor(a: Assessment): string`, which returns `Handhold: this request scores ${dim} ${score}/3 (technique: ${technique}). Before doing the task, offer in one or two lines the more ambitious version — e.g. "${a.rewrite}" — then proceed with what was asked unless the user takes it up.`
  - `type Backoff = { offered: Technique | null; declines: Partial<Record<Technique, number>> }`. The atom is `handhold.backoff`.
  - `recordOutcome(b: Backoff, nextPrompt: string, lastRewrite: string): Backoff`: the person "took it up" when the next prompt shares at least 3 content words (length ≥ 5, case-insensitive) with `lastRewrite`. Otherwise `declines[offered]++`.
  - `isSuppressed(b: Backoff, t: Technique): boolean`, which is `(b.declines[t] ?? 0) >= 2`
  - `registerNudge(on: On, cfg: Config, capture: CaptureApi): void`, which registers:
    - `prompt.compose`: `next(e)`, then append `BRIEF` unless one with that id is already present.
    - `prompt.submit` (skip `command`/`isMeta`/`isTrivial`): `recordOutcome` first, then `judge` pre. When `needsNudge` and not suppressed, `next({ ...e, context: [...(e.context ?? []), hintFor(a)] })` and set `backoff.offered`. Push `a` onto the atom `handhold.recent` (keep the last 5). Hold `a` for `addSpan` on the next `turn.start`, keyed by the prompt text, so back-to-back prompts never cross (Review Focus 4).

### Task 7: Post-answer judge, visible note and `/handhold` commands

**Files:**
- Create: `plugin/src/nudge/note.ts`, `plugin/src/shared/commands.ts`
- Modify: `plugin/hooks/register.ts`, `plugin/types/index.d.ts`, `plugin/test/nudge.test.ts`

**Interfaces:**
- Consumes: `judge`, `needsNudge`, `assessAttrs`, `CaptureApi`
- Produces:
  - `noteText(a: Assessment): string`, which returns `` `Handhold · ${cap(a.opportunity)} ${a.scores[a.opportunity]} → try: "${a.rewrite}"` ``
  - `shouldShowNote(s: { quiet: boolean; turnsSinceNote: number }, a: Assessment | null, every: number): boolean`
  - `summarize(t: ClosedTurn): string`, which returns `tools: ${toolNames.join(', ') || 'none'}; subagents: ${agentTypes.join(', ') || 'none'}; aborted: ${isAborted}; answer: ${answer.slice(0, 400)}`
  - `registerNote(on, cfg, capture)`: a main-loop `turn.complete` hook that does `const r = await next(e)`, runs the post judge on the turn, `addSpan`s `handhold.assess` (phase `post`), and returns `{ ...r, text: noteText(a) }` only when `shouldShowNote`. Otherwise it returns `r`. The atoms are `handhold.quiet` and `handhold.turnsSinceNote`.
  - `registerCommands(on, handlers: Record<'review'|'export'|'quiet'|'pane', (args: string) => Promise<{ text: string }>>)`: registers `/handhold` at `session.start` and routes `command.run` `{ command: 'handhold' }` on the first word of `args`. An unknown word answers `Usage: /handhold review [session|week] | export [--otlp] [--report <path>] | quiet [off] | pane`.
